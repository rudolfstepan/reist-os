# Native bounded task pool — R8.3an

Frozen after accepted `0f4efd17`, 14 September2026. Continuous interactive
native completion authorizes this next cohesive process-capacity transaction,
not a change to R8.3am's closed gates or its historical failed evidence.
Exactly one active implementation package, visible main worktree, no agent,
push, physical device, writable media or host configuration change.

## Inventory and failure boundary

Identity and FIFO/deadline cores already admit explicit capacities up to64.
The native run descriptor, family records, two imported image owners, IPC
clients/completions, heap state and scheduler backing remain fixed at four.
Changing only a slot comparison would permit out-of-bounds ownership and lost
cleanup. They therefore form one allocation/publication/retirement boundary.
The demonstrated limitation is architectural capacity, not a diagnosed crash.

Reuse the existing generation-bearing task identity, task/frame/profile/FP
cores, sole intrusive wait node, native IPC completion, heap continuation,
prepared image and family ownership. No second scheduler, allocator, ELF
parser, capability domain or service policy. The larger exact heap metadata
and its boot reservation are necessary backing for these same eight owners;
their independently validated inner/outer layout is part of this transaction.

## Explicit profile and compatibility

Add opt-in NativeTaskPool / X86_64_NATIVE_TASK_POOL=1, requiring plain
NativeWide/Import/Startup/Lifecycle/Programs/Runtime/Heap/IPC/RAM. Reject
PIO/block/filesystem/file-launch and unrelated fault selectors before outputs.
This package grants no new device authority; adapting device-owner slots or
ordinary shell integration remains the corresponding subsequent boundary.
Default selectors, native four-slot profiles and i386 remain unchanged.

Standard reference remains SysV AMD64, ELF64 ET_EXEC, existing REIST-v1
syscall/errno and explicit generation-scoped TASK_CONTROL adapter. No public
syscall number or structure change. Existing CREATE versions1..5, WAIT/CANCEL,
argv/environment and attenuated full profiles retain their meaning. Numeric
handles are not authority. The selected new finite platform profile admits
slots0..7; old profiles still reject target slots4 and above.

A private run-v4 is272 bytes: the existing16-byte header followed by eight
unchanged32-byte task descriptors. Exactly two initial roots0/1 and six dynamic
slots2..7. Roots have argument1, children0; private imported IDs7..12 belong
only to slot=image-5. Catalog IDs3..6 retain their identity and shared immutable
semantics. Old run-v1..3 remain144 bytes and never imply eight-slot authority.
All active and unused fields and every backing capacity must agree before
first allocation/publication. Bad counts, versions, sizes, aliases or masks
must fail closed without partial pool initialization.

Legacy bootstrap probes continue using their original four-slot active pools;
larger backing must not silently expand a legacy probe. Native run-v4 alone
activates eight task/ready/deadline slots with one node per live task. Full
identity/profile/context/queue checks cover every active slot, including7.
Storage capacity, active capacity and the fixed two-root policy are distinct.
Neither an unused backing slot nor a copied descriptor confers authority.

Per-generation CPU samples remain1..32, CREATE attempts remain eight per root,
WAIT1..1000ms, Sleep1..100ms, existing heap byte/region/table limits unchanged.
No reset on sleep/yield/IPC/wait/replacement, no periodic replenishment,
unbounded service lifetime, hidden restart or relaxed interrupt lease.
At most18 admitted family lifetimes per run (two roots plus16 attempts);
six simultaneous dynamic children do not enlarge either parent's budget.

## Coupled memory and retirement

Extend only opt-in backing for eight identities, FP states, CPU profiles,
page tables, completion seals, IPC clients/pending requests and heap owners.
Existing per-owner layouts and fixed-capacity critical-object validation stay.
Every slot participates in cancellation, owner loss, deadlines, fences, orphan
receipts, staged image release, heap continuation and final zero/free balance.
Terminal receipts occupy a slot until collected but never retain frame rights.
Stale generations cannot address a replacement or another parent's child.

Introduce private C layout5 only for the exact eight-owner heap state.
Keep layout2/3/4 bytes and mappings unchanged. Preserve the existing memory
state and heap start0x653000; admit exactly the derived eight-owner size and
rounded appended page-table arena, wholly below native catalog0xa00000.
Linker, producer, outer verifier and boot initializer must agree on exact
sizes, addresses, NOLOAD/RW/NX and reserved extents. No generic extra PT_LOAD,
file/BSS alias, moved fixed bridge, weakened W^X or direct-map writable alias.
Reject partial, mislabeled, overlapping or oversized bindings before handoff.
