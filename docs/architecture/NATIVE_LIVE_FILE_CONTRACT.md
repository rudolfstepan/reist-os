## Existing mechanisms and standard-first boundary

Reuse the System V ELF64/AMD64 executable representation and existing bounded
Ring3 ELF adapter, FAT12/FAT16/ext2 readers, generation-scoped task and IPC ABI,
and ATA read-only driver. Their documented REIST restrictions remain; no new
compatibility claim, parser, public syscall or persistent format. Existing
NativeFileLaunch remains unchanged: its four-slot fixture intentionally retires
the services before import. The accepted eight-slot pool removes that capacity
restriction; CREATE-v6 supplies the accepted periodic service budget.

NativeLiveFile composes the existing TaskPool/PoolPIO/FileLaunch mechanisms,
without selecting the old ServicePIO workload. Slot0 supervises, slot1 is an
unrelated finite peer, slot2 the real ATA service, slot3 the real filesystem,
slot4 the independently file-loaded application. The driver and filesystem use
CREATE-v6 with32 samples/1000ms; the application retains CREATE-v5 lifetime32.
No kernel, assembly, SDK or driver source change is permitted.

## Lifetime and authority

Use the existing generated read-only disk and exact disposable-overlay guard.
Start, bind, self-test and establish the driver/filesystem session as before.
Capture the actual file with the unchanged file-image SDK and1800ms bound,
validate ELF and wipe workspace. Retain service generations and their IPC
endpoints through application import. Import into slot4, erase prepared image
and startup source, and delegate only SEND/RECEIVE on a separate private app
channel. Never overwrite the live filesystem endpoint or grant the app device,
task-control, filesystem endpoint or management rights.

The app validates its existing startup and denied device/control operations,
sends its generation-bound ELF64RO! acknowledgement, then blocks on its private
channel for at most1000ms. The root issues one real filesystem STAT while both
services and the loaded app remain live, then sends a canonical fixed GO
message. No timing-only sleep is accepted as proof of coexistence. Validate
version, size, exact payload, generation and zero tail before app continuation.
The new qualification executable is at most1280bytes, leaving one of the
existing eight FS requests after capture. The public SDK limit stays1536bytes;
FS8, block16, ATA200ms, RPC1000ms, profile2800ms/session3000ms stay unchanged.

Run two bounded generations in each of two kernel process runs. Normal exit,
application fault/cancel, service crash/hang/quota/bad reply and owner loss use
the same detect/isolate/fence/revoke/reap ordering. Physically fence the driver
before either dependency is reaped. Preserve terminal receipts, reject stale
generations, close endpoints and use fresh generations/self-tests on replacement.
Loaded bytes are privately owned, not invalidated by service failure. Parent
loss retires all descendants; the independent peer must remain functional.
No in-place repair, budget reset, hidden retry or implicit restart authority.
